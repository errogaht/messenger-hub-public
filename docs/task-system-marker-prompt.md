# Промпт для агента системы задач

В Messenger Hub0.7.0 появился messenger_message_mark для рабочих реакций на исходные
сообщения Telegram и WhatsApp. Используй его в уже разрешённом владельцем workflow:
viewed = 👀 (прочитал полный источник), in_progress = 👨‍💻 (взял задачу в работу),
completed = ✅ (результат проверен), question = 🤔 (есть вопрос/блокер).

Передавай точные connectionId, conversationId, messageId, status и стабильный
requestId для каждого перехода. Например:
{"connectionId":"telegram-main","conversationId":"<точный ID чата>","messageId":"<ID исходного сообщения>","status":"in_progress","requestId":"<taskId>-<messageId>-inprogress-v1"}

Реакции ставит подключённый аккаунт владельца. Названия чатов/имена не являются ID.
В Telegram завершение — зелёная custom-галочка, остальные наши рабочие реакции
заменяются, посторонние сохраняются. В WhatsApp заменяется единственная наша реакция.

Не превращай любую переписку в задачи. Отмечай только источники реальной выбранной
задачи. viewed ставь после полного чтения текста/нужных вложений/транскрипции,
completed — после фактической проверки результата и необходимой публикации.
Если сообщение относится к нескольким задачам, не помечай completed до завершения
всех относящихся к нему поручений. Реакция не заменяет tracker, Markdown или inbox ack.

Повтор с тем же requestId и тем же payload безопасен: Hub возвращает прежнюю квитанцию.
Для новой стадии нужен новый requestId. При unknown не отправляй заново и не создавай
новый ID: вызови messenger_message_mark_result с connectionId/requestId. Telegram
может восстановить подтверждение чтением своей реакции; у WhatsApp потерянный ответ
может остаться unknown. Не утверждай, что маркер установлен без подтверждения.
При failed/запрете реакции сообщи владельцу безопасную причину; не меняй учётную
запись/права и не заменяй реакцию клиентским сообщением. Read-only scope не даёт права
ставить реакции. Не включай новые каналы или grants ради использования инструмента.

Если новых инструментов нет в старой MCP-сессии, переподключи Messenger Hub: сервер
уже публикует их. Не обходи readonly grants альтернативным аккаунтом/API.
